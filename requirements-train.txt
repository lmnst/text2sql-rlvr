# --- non-obvious workarounds that make this set run on Blackwell -------------
#
# 1. torch 2.11.0 has a Blackwell import bug (PyTorch #186220): torch._inductor
#    re-registers flex_attention templates and grouped_mm extern kernels. Patch
#    torch/_inductor/select_algorithm.py by commenting out two asserts:
#      assert name not in self.all_templates, "duplicate template name"
#      assert not hasattr(extern_kernels, name), f"duplicate extern kernel: {name}"
#    (Safe: we run sdpa + enforce_eager, never torch.compile.)
#
# 2. verl 4a2cba7's attention_utils.py hard-imports flash_attn.bert_padding.
#    Patch it to fall back to transformers.modeling_flash_attention_utils
#    (_unpad_input/_pad_input/_index_first_axis) + einops.rearrange.
#
# 3. verl 0.9 renamed the custom reward config to reward.custom_reward_function
#    (path/name). The legacy migrate_legacy_reward_impl() is only called on the
#    fully-async path, so on main_ppo.py the top-level custom_reward_function key
#    is silently ignored. Always write reward.custom_reward_function.path/name.
#
# 4. verl 0.9 rollout defaults tensor_model_parallel_size=2; single GPU needs
#    actor_rollout_ref.rollout.tensor_model_parallel_size=1.
#
# 5. verl 0.9 agent.num_workers defaults 8; batch size must be divisible by it
#    (set actor_rollout_ref.rollout.agent.num_workers to match the smoke batch).
#
# 6. vllm serve on SM120 crashes in flashinfer sampling ("FlashInfer requires
#    GPUs with sm75 or higher" -- capability detection fails on sm_120, vLLM PR
#    #44405). Start serving with:
#      VLLM_USE_FLASHINFER_SAMPLER=0 VLLM_ATTENTION_BACKEND=TRITON_ATTN \
#      vllm serve <model> --enforce-eager ...
